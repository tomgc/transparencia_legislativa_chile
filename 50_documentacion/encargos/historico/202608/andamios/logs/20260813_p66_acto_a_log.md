## Antes de G0: lo que hubo que destrabar

El encargo llegó bloqueado por su propia hipótesis **H6** («la rama
`sondeo/p68-fuentes-tematicas` fue mergeada y `50_veredicto_fuentes_tematicas_bcn.md`
está en `main`»). Era falsa, y el punto 2 de G0 ordena detenerse si lo es.

Secuencia real, en tres intentos separados por decisiones del titular:

1. La rama del sondeo ni siquiera estaba publicada. Se publicó y se abrió el
   **PR #13**.
2. El PR quedó **abierto**. Un intento de continuar leyó `merge_commit_sha =
   d34aa4b…` en la API, que **no es prueba de merge**: en un PR abierto y
   mergeable GitHub publica ahí su merge *especulativo*. Se descartó midiendo:
   `git cat-file -t d34aa4b` → *could not get object info*, y
   `git merge-base --is-ancestor d34aa4b origin/main` → falso.
3. Con autorización explícita del titular se ejecutó `gh pr merge 13 --merge`.
   `merged = TRUE`, `merged_at = 2026-08-13T18:32:20Z`, merge commit `4f187be`.

**Nota metodológica que vale para el acto B:** la vista de archivos de un PR en
la API queda anclada a `base.sha` del momento de creación. Durante todo el
episodio el PR #13 mostró **4 archivos, incluido `CLAUDE.md`**, y no se
recalculó ni tras 12 sondeos a lo largo de dos minutos. Lo que el merge
efectivamente aplicaría se midió con `git merge-tree --write-tree`: **3
archivos, 1667 inserciones, `CLAUDE.md` con md5 idéntico**. El merge real
confirmó exactamente eso. **La vista del PR no es la medición del merge.**
